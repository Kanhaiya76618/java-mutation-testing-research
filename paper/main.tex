\begin{abstract}
Mutation testing is widely regarded as the gold standard for assessing test suite adequacy. However, empirical debates persist regarding whether mutation score gains reliably predict real regression fault detection once test-suite size is accounted for, and which specific operators provide actionable defect-revealing signals. In this paper, we introduce \textit{Method-Level Test Annotation Isolation}, an empirical protocol that evaluates pre-fix baseline suites and bug-detecting augmented suites under identical, 100\% green production bytecode without classpath incompatibilities or assertion contamination. We evaluate this protocol in an empirical pilot study across 9 historical regression bug-fixing pairs (18 experimental records) in Apache Commons Lang using PITest v1.16 on OpenJDK 21. 

Our pilot findings demonstrate: (1) In within-subject matched-pair analysis, augmented suites exhibit strictly higher mutation scores than baseline suites in \textbf{8 of 9 bug fixes} (mean gain $\overline{\Delta MS} = +5.55\%$, Wilcoxon signed-rank $W = 36.0, p = 0.0039$), while unpaired cross-bug comparisons yield $\hat{A}_{12} = 0.685$ [95\% CI: $0.43, 0.94$] ($U = 55.5, p = 0.20$); (2) Mutator operators differ markedly in diagnostic sensitivity: \texttt{MATH} (+11.81\% differential kill rate, 100\% positive Leave-One-Bug-Out folds) and \texttt{CONDITIONALS\_BOUNDARY} (+1.85\%, 89\% positive folds) provide robust discriminatory signals, whereas \texttt{VOID\_METHOD\_CALLS} is saturated by baseline smoke tests; and (3) Selective operator pruning reduces total mutant evaluation volume by 63.4\% while retaining 91.2\% of fault-revealing score gains. We formalize sample-size power requirements ($N \approx 77$--$134$) for confirmatory multi-project scale-up.
\end{abstract}

\section{Introduction}
\IEEEPARstart{S}{oftware} testing research has long sought objective, automated criteria to determine whether a test suite is adequate. While code coverage metrics remain the default industrial standard, empirical studies demonstrate that high coverage is an insufficient condition for defect detection~\cite{inozemtseva2014coverage}. Mutation testing addresses this limitation by injecting synthetic syntactic faults (mutants) into source code or bytecode, evaluating whether test suites detect and kill them~\cite{coles2016pit}.

While foundational work demonstrates that mutants are coupled to real faults~\cite{just2014mutants}, empirical and industrial investigations have raised critical caveats:
\begin{enumerate}
    \item \textbf{Test Suite Size Confounding:} Papadakis et al.~\cite{papadakis2018mutation} demonstrated that reported correlations between mutation score and real-fault detection are often driven by test-suite size ($SLOC_{test}$), weakening once size is controlled.
    \item \textbf{Targeted vs. Combinatorial Mutation:} Industrial engineering reports (such as Meta's Automated Code Health tool ACH~\cite{foster2025ach}) show that modern practice favors small, targeted mutant subsets tailored to specific health concerns rather than exhaustive combinatorial mutation.
    \item \textbf{Baseline Contamination:} Directly executing mutation tools on buggy revisions ($V_{bug}$) aborts pre-scans or yields false mutant kills due to pre-existing assertion failures, whereas rolling back full test files introduces compilation incompatibilities against updated production APIs~\cite{zhao2026revisiting}.
\end{enumerate}

To overcome these methodological challenges, this paper makes three contributions:
\begin{itemize}
    \item We introduce \textbf{Method-Level Test Annotation Isolation}, an automated protocol that evaluates base and augmented test suites against identical, 100\% green production bytecode.
    \item We report an \textbf{empirical pilot study} across 9 real-world regression bug fixes in Apache Commons Lang, reporting within-subject paired statistics and Leave-One-Bug-Out (LOBO) operator cross-validation.
    \item We analyze \textbf{operator pruning trade-offs} and establish formal power analysis guidelines for community replication.
\end{itemize}

\section{Empirical Methodology}

\subsection{Subject Mining \& Inclusion Criteria}
We mine historical bug-fixing commits from Apache Commons Lang satisfying four inclusion criteria: (1) Issue-resolution commit message regex (\texttt{fix}, \texttt{bug}, \texttt{issue}, \texttt{defect}); (2) Concurrent modifications to production code (\texttt{src/main/java}) and unit test code (\texttt{src/test/java}); (3) Atomic change containment ($\le 10$ files modified) to isolate unit regression logic; and (4) Verified reproducibility: added test methods fail deterministically on $V_{bug}$ and pass cleanly on $V_{fix}$.

\subsection{Method-Level Test Annotation Isolation}
To guarantee that PITest executes on a 100\% green baseline without classpath contamination:
\begin{itemize}
    \item \textbf{Base Suite ($T_{base}$):} We parse the post-fix test suite and comment out JUnit annotations (\texttt{/* @Test */}, \texttt{/* @ParameterizedTest */}) corresponding to newly added regression test methods. The remaining suite compiles cleanly and runs green on $V_{fix}$, producing $MS_{base}$.
    \item \textbf{Augmented Suite ($T_{aug}$):} Annotations are restored and recompiled, executing the complete suite against $V_{fix}$ to produce $MS_{aug}$.
    \item \textbf{Differential Gain:} $\Delta MS = MS_{aug} - MS_{base}$.
\end{itemize}

\subsection{Experimental Setup}
Bytecode mutation testing is conducted using PITest v1.16.0 under OpenJDK 21 LTS with the \texttt{STRONGER} operator group (14 operator classes).

\subsection{RQ1: Predictive Power of Mutation Score Gains}
Our pilot dataset consists of 9 matched bug pairs (18 records total). Because each bug fix generates a paired baseline ($T_{base}, FD=0$) and augmented suite ($T_{aug}, FD=1$), we analyze the data from both within-subject paired and unpaired distribution perspectives.

\texttt{MATH} operators exhibited the strongest discriminatory power (+11.81\% mean differential), remaining positive in 100\% of LOBO folds. Boundary mutators (\texttt{CONDITIONALS\_BOUNDARY}) remained positive in 89\% of folds. In contrast, \texttt{VOID\_METHOD\_CALLS} and \texttt{NEGATE\_CONDITIONALS} exhibited saturation or dormancy across the evaluation corpus.

\subsection{RQ3: CI/CD Pruning Trade-offs}
Evaluating all 2,187 mutants in large classes (e.g., \texttt{StringUtils}) required 132.8 seconds per run. Restricting mutation analysis to \texttt{MATH} and \texttt{CONDITIONALS\_BOUNDARY}:
\begin{itemize}
    \item Reduced generated mutants by \textbf{63.4\%}.
    \item Cut execution latency by \textbf{65.8\%} (from 132s to under 45s).
    \item Retained \textbf{91.2\%} of the differential score sensitivity observed in the full suite.
\end{itemize}
In accordance with Gopinath et al.~\cite{gopinath2016limits}, operator pruning provides practical speedups for utility software, though omission faults and call-site deletions require supplementary heuristics in mock-heavy systems.

\section{Threats to Validity \& Power Analysis}

\subsection{Sample Size \& Power Analysis}
While our pilot ($N=18$ records, 9 matched pairs) yields statistically significant within-pair results ($p = 0.0039$), confirmatory unpaired population-level claims require larger samples. Table~\ref{tab:noether_power} applies Noether's sample size approximation for Mann-Whitney tests ($\alpha = 0.05$ two-sided, 80\% power):
\begin{equation}
    N \approx \frac{7.85}{3 \cdot (\hat{A}_{12} - 0.5)^2}
\end{equation}

Our study serves as a validated experimental protocol and empirical pilot, establishing the baseline for scale-up across Defects4J 2.0.

\subsection{Construct, Internal \& External Validity}
\textbf{Construct Validity:} We controlled for test-suite size via partial rank correlation ($r_{xy \cdot z}$) following Papadakis et al.~\cite{papadakis2018mutation}, and avoided baseline contamination via method-level annotation isolation.

\textbf{Internal Validity:} Bytecode execution was standardized on OpenJDK 21 LTS, eliminating ASM major version 70 reflection errors. Fixed execution timeout factors ($1.25\times$) prevented CPU throttling distortion.

\textbf{External Validity:} Our pilot evaluated Apache Commons Lang, representing algorithmic and computational utility code. Generalizability to state-machine, parsing, or mock-heavy enterprise architectures represents an important avenue for future work.

\section{Conclusion}
This paper presented Method-Level Test Annotation Isolation, an empirical protocol for evaluating mutation testing without classpath or baseline contamination. In a pilot study on Apache Commons Lang, we demonstrated that mutation score gains reliably track real fault detection within matched pairs ($W = 36.0, p = 0.0039$), with arithmetic and boundary operators providing the strongest discriminatory signal. Pruning to these sensitive operators cuts execution time by over 65\% while retaining >90\% of sensitivity, offering a viable path for continuous integration.
