# Research Brief: Java Mutation Testing for Regression-Test Fault Detection

*Anchored in empirical software engineering literature (2014–2026).*

---

## 1. Foundational Literature & Motivations

1. **Zhao, Zhou & Cohen (2026), "Do Coverage and Mutation Scores of LLM-Generated Test Suites Correlate with Their Effectiveness? (Replicability Study)"**
   - Junda Zhao, Shurui Zhou, Eldan Cohen. *Proceedings of the ACM on Software Engineering* (ISSTA 2026), arXiv:2607.22880, DOI: 10.1145/3832093.
   - Replicates two earlier studies of coverage, mutation score and real-bug detection using test suites generated by many LLMs.
   - Finds the metrics informative when comparing models on code assumed bug-free, but unreliable when the code under test is already buggy and the goal is to expose that bug.

2. **Papadakis et al. (2018), "Are mutation scores correlated with real fault detection? A large scale empirical study on the relationship between mutants and real faults"**
   - *ICSE 2018*, pp. 537–548, DOI: 10.1145/3180155.3180183.
   - Shows that much of the reported correlation between mutation score and real-fault detection comes from test-suite size and is weak once size is controlled.
   - Direct motivation for comparing equal-size test subsets (`scripts/subset_analysis.py`).

2b. **Chen et al. (2020), "Revisiting the relationship between fault detection, test adequacy criteria, and test set size"**
   - *ASE 2020*, pp. 237–249, DOI: 10.1145/3324884.3416667.
   - Argues that correlation at a fixed test-set size is the wrong question and proposes a probabilistic framing instead.

3. **Just et al. (2014), "Are mutants a valid substitute for real faults in software testing?"**
   - *FSE 2014*, DOI: 10.1145/2635868.2635929.
   - Analyzed 357 real faults in 5 open-source Java projects, demonstrating that mutant kill rates are significantly correlated with real fault detection beyond code coverage, driven by the coupling effect.

4. **Foster et al. (2025), "Mutation-Guided LLM-based Test Generation at Meta"**
   - *FSE 2025 Companion (Industry track)*, pp. 180–191, DOI: 10.1145/3696630.3728544.
   - Describes Meta's ACH system (Automated Compliance Hardening), which generates a few targeted mutants for a specific concern (e.g. privacy) and uses LLMs to write tests that kill them, instead of exhaustive mutation.

5. **Gopinath, Alipour, Ahmed, Jensen & Groce (2016), "On the limits of mutation reduction strategies"**
   - *ICSE 2016*, pp. 511–522, DOI: 10.1145/2884781.2884787.
   - Highlights that random mutant sampling is a formidable baseline, establishing rigorous standards for evaluating operator pruning and selective mutation strategies.

6. **Chekam, Papadakis, Le Traon & Harman (2017), "An empirical study on mutation, statement and branch coverage fault revelation that avoids the unreliable clean program assumption"**
   - *ICSE 2017*, DOI: 10.1109/ICSE.2017.61.
   - Compares how well mutation, statement and branch coverage reveal real faults without assuming the program under test is clean.

## 2. How T_base and T_aug Are Built (Method-Level Test Annotation Isolation)

> Note (October 2026): comparing MS(T_aug) with MS(T_base) alone cannot show that mutation score
> tracks bug detection, because T_aug is T_base plus tests. The suites below are now inputs to the
> placebo and equal-size subset analyses; see `PITFALL_ANALYSIS.md` and `SUBSET_ANALYSIS.md`.

Directly executing mutation tools like PITest on buggy source code ($V_{bug}$) aborts execution or yields false mutant kills due to pre-existing assertion failures. Conversely, checking out pre-fix test files against modern production code ($V_{fix}$) triggers compilation errors when tests reference modified APIs.

**Our Protocol:**
- **Pre-Fix Verification:** Confirm that developer-added test methods fail against $V_{bug}$ and pass on $V_{fix}$.
- **Base Suite ($T_{base}$):** Comment out test annotations (`/* @Test */`, `/* @ParameterizedTest */`) on newly added regression test methods, allowing PITest to evaluate a 100% green suite against $V_{fix}$ to produce $MS_{base}$.
- **Augmented Suite ($T_{aug}$):** Restore annotations and recompile, evaluating the complete test suite against $V_{fix}$ to produce $MS_{aug}$.
- **Differential Gain:** $\Delta MS = MS_{aug} - MS_{base}$.

- **PIT (PITest v1.16.0)**: Bytecode-level Java mutation testing framework.
