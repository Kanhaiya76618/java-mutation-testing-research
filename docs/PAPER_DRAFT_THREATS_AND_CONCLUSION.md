## 5. Threats to Validity

Every empirical software engineering investigation faces threats that may affect the interpretation or generalizability of its findings. We address these threats across four established dimensions (Wohlin et al., 2012).

### 5.1 Construct Validity
*Construct validity concerns whether our operational measures accurately reflect the theoretical constructs under study.*
* **Proxy Metric Fidelity:** We operationalize fault detection capability via bytecode mutants generated by PITest. Although mutants are synthetically injected syntactic modifications, previous theoretical foundations (Competent Programmer Hypothesis and Coupling Effect) argue they reflect the distribution of real human errors. To minimize artificial divergence, we utilized PITest's `STRONGER` mutator set rather than naive trivial mutators.
* **Test Suite Expansion Confounding:** An obvious threat is that adding tests increases code coverage and suite size ($SLOC_{test}$), trivially increasing mutation score without indicating higher defect detection quality. We explicitly mitigated this threat by computing **size-controlled partial rank correlation ($r_{xy \cdot z}$)**, holding test suite size constant while measuring the direct correlation between $\Delta MS$ and real fault detection.
* **Base Suite Execution Hygiene:** Executing PITest directly against pre-fix source code triggers compile errors or false mutant kills due to pre-existing failing assertions. Our method-level annotation isolation (`/* @Test */`) guarantees that both $T_{base}$ and $T_{aug}$ run against the exact same production bytecode $V_{fix}$ with a 100% green baseline.

### 5.2 Internal Validity
*Internal validity concerns the presence of confounding variables that could bias causal inferences.*
* **JVM and Bytecode Non-Determinism:** Java 26 introduces bytecode major version 70, which causes ASM 9.x to throw reflection incompatibilities on JDK internal types. We standardized all compilations and PITest executions on **OpenJDK 21 LTS**, with explicit `JAVA_HOME` scoping in all harness wrappers.
* **Test Flakiness & Timeout Thresholds:** PITest relies on timeout thresholds to classify infinite loops caused by mutations. We enforced a fixed timeout factor ($1.25\times$ baseline test runtime) and executed sequential headless runs on an isolated Apple Silicon host to prevent CPU throttling and timeout skew.
* **Commit Atomicity:** Bug-fixing commits that combine architectural refactorings or dependency updates could introduce unrelated test changes. We programmatically filtered our mining corpus to atomic commits modifying $\le 10$ files and strictly requiring concurrent edits to `src/main` and `src/test`.

### 5.3 External Validity
*External validity concerns the extent to which our conclusions generalize beyond the experimental subjects.*
* **Subject Representativeness:** Our benchmark currently evaluates Apache Commons Lang, a mature, mission-critical Java library widely used across enterprise applications. While Commons Lang is representative of foundational computational, algorithmic, and data-structure utilities, our findings may differ in systems dominated by asynchronous I/O, relational database transactions, or distributed microservice orchestration.
* **Language & Framework Boundaries:** We specifically evaluated Java and JUnit 5 with PITest. Differences in language semantics (e.g., dynamic typing in Python with MutPy, or memory ownership in Rust with cargo-mutants) might exhibit distinct operator sensitivities.

### 5.4 Conclusion Validity
*Conclusion validity concerns the statistical soundness of the relationship between treatment and outcome.*
* **Non-Parametric Assumptions:** Because mutation score distributions and fault detection binary variables violate normality assumptions, we avoided Pearson correlation and Student's t-tests. Instead, we strictly reported non-parametric statistics: Spearman’s $\rho$, Kendall’s $\tau$, Vargha-Delaney’s $\hat{A}_{12}$, and Cliff’s $\delta$.
* **Sample Size & Effect Size Dominance:** Although our dataset consists of 18 records across 9 distinct bug pairs, we emphasized standardized non-parametric effect sizes ($\hat{A}_{12} = 0.685$, Medium-to-Large effect) rather than relying exclusively on p-value significance.

## 6. Conclusion & Future Directions

In this work, we conducted an empirical study investigating the real-world fault-detection fidelity of Java bytecode mutation testing. By mining historical bug-fixing commits and introducing method-level test annotation isolation, we evaluated the predictive power of PITest without contaminating baseline test validity.

Our principal findings demonstrate:
1. **Mutation score gains have a positive, medium-strength correlation with real regression fault detection ($r_{xy \cdot z} = 0.324$, $\hat{A}_{12} = 0.685$)**, even after rigorously controlling for test suite size.
2. **Mutator operators are not created equal:** `MATH` and `CONDITIONALS_BOUNDARY` operators provide the strongest discriminatory signal for regression bugs, while `VOID_METHOD_CALLS` and `INVERT_NEGS` suffer from saturation.
3. **Selective operator pruning** eliminates over 60% of computational overhead while preserving >90% of fault-detecting mutant kills, providing a concrete path toward practical CI/CD integration.
